## 1. A10: `--frontier-policy {record,stop}`

- `FrontierPolicy` (`walking/work_policy.rs`): `Record` (default, the historical behaviour) keeps walking
  past committed frontiers; `Stop` saves the checkpoint and stops cooperatively (exit 4, stop reason
  `frontier_policy`) at the first frontier the session commits. Frontiers stay explicit, persisted and
  blocking certification under both policies; only continuation differs.
- Trigger: the committed frontier count at session start (0 for a fresh walk, so initial input frontiers
  stop it before any inspection; the restored count on resume). It fires at most once per session, at a
  checkpoint opportunity, and persists exactly the state that contains the new frontier's record (forced
  final save labelled `stop_reason: frontier_policy` in the manifest metadata), journals a
  `frontier_stop` event, then cancels like a stop request. Resuming is the operator's explicit decision
  to continue to the next new frontier.
- Binding: `Stop` is bound into the CP5 request binding; `Record` adds no key, so every existing CP5
  checkpoint and control keeps its digest (a test restates the pre-A10 formula and compares digests).
  A Stop checkpoint refuses a Record resume and vice versa. Record receipts are byte-identical (no new
  keys); Stop receipts add `frontier_policy` and, when fired, `stop_reason`.
- Admission: Stop requires a checkpointed Ordered or Ready walk.
- CLI `rustred owner-domain-match --follow-successors --frontier-policy {record,stop}` (stop needs
  `--checkpoint` or `--resume`); thin Python driver
  `match_shared_owner_domains.py` (requires `--follow-successors` and a checkpoint); supervisor
  `shared_owner_campaign.py` forwards and records it (request, status, summary, resume command; the
  monitor shows `PAUSED · stop frontier_policy`); the production launcher freezes `stop` for new
  campaigns (steering schema v3) and keeps `record` for steering written before the option existed.
- The CLI journal (`--events`) records `frontier_stop` as a milestone next to the checkpoint events (the
  first drill found it dropped by the journal's event allow-list; fixed, with a unit test).

## 2. Host-aware RAM guard (`shared_owner_campaign.py`)

`RamGuard` is a pure state machine over /proc readings (tests drive it with fake readers).

| Trigger | Kind | Default |
|---|---|---|
| aggregate RSS of the supervised tree reaches soft = hard x (1 - margin) | cooperative save-and-stop (exit 4) | margin 5% |
| host (or enclosing cgroup) MemAvailable falls to the floor | cooperative save-and-stop | **floor 50 GB** |
| host-wide swap-in (`/proc/vmstat pswpin`) at or above a rate in every sample for a window | cooperative save-and-stop | 32 MiB/s for 120 s (0 disables) |
| RSS reaches hard, or MemAvailable falls to a quarter of the floor | SIGKILL of the owned native | 12.5 GB emergency |

- **Floor default (owner decision 2026-09-27): a flat 50 GB** (`DEFAULT_HOST_MEMORY_RESERVE_BYTES`),
  replacing `min(20 GB, 5% of host/cgroup RAM)`. It is configurable with `--host-memory-reserve-bytes`
  (alias `--host-available-floor-bytes`). Admission leaves the floor free; a host or cgroup with less
  than the floor available is refused with a message naming the flag, so small hosts must pass an
  explicit floor. The production launcher freezes the 50 GB value explicitly into new steering and it
  may be overridden per resume like the other RAM options; steering frozen before the option existed
  gets the supervisor default (now also 50 GB).
- Every resource sample records MemAvailable, the ZFS ARC size (`arcstats size`, counted as used by the
  kernel and shrinkable to `c_min`), the swap-in rate and sustained seconds, and the native's `VmSwap`;
  the summary records the policy, the initial host snapshot, the minimum observed MemAvailable and the
  maximum observed ARC.
- Liveness: the production launcher refuses `--resume` after `--max-zero-progress-ram-stops` (default 2)
  consecutive RAM-guard stops without committed progress (the legacy walk has no per-ID attempt counter,
  so a head whose inspection alone trips the guard would otherwise loop).

Tests [M]: `examples/python/test_ram_guard_frontier_policy.py` (13: fake /proc readers, the guard state
machine and its validation, the 50 GB default and an explicit floor, a supervised fake native stopped by
sustained swap-in, the frontier stop forwarded and reported, thin-driver validation, production steering
v3 and legacy steering, liveness streaks and the refused looping resume); admission expectations in
`test_shared_owner_campaign.py` updated to the 50 GB floor. Python suite: 239 tests OK, 1 skipped.

## 3. Timing-flaky tests

Isolated runs did not reproduce the handoff's flakes (baseline binary under 16 nice-19 burners:
`cli::shards` x200 and `ready_late_native_fault...` x200, 0 failures [M]). Equal-priority contention did:
12 concurrent test processes on the 16 lane CPUs for 600 s (`TMP/ops/contend.sh`) [M]:

| filter (4 loops each) | baseline e6a2c23c (runs / failures) | hardened (runs / failures) |
|---|---|---|
| `cli::shards` | 5,068 / 7 (ETXTBSY at `launch().unwrap()`) | 5,028 / 0 |
| `walking::execution::ready` | 1,349 / 211 (`ready_changed_parked_prefix_fails_before_any_suffix_admission`, left 18 right 17) | 1,230 / 0 |
| `walking::parallel` | 8,645 / 0 | 8,527 / 0 |

Run directories `TMP/ops/contend-baseline/` and `TMP/ops/contend-step3/` (worktree `TMP/`).

- `crate::test_gates::isolated(path)` (app and core): the parent test re-executes the test binary filtered to
  exactly that test (`--exact --test-threads=1`), requires `1 passed`, forwards the child's skip markers, and
  returns; the child runs the body with no sibling in the process.
- `orphan_child_retains_campaign_lock_until_exit` and the four `cli::shards` tests that write and exec a fake
  executable run isolated: a sibling that forks while this test holds a descriptor keeps a copy until its own
  exec, so a released lock can stay held and exec of the just-written fake fails with ETXTBSY.
- `persistence::catalog::tests::arbitrary_exact_expressions_roundtrip_with_deduplicated_values` (core) runs
  isolated: the partial Symbolica state export appends every variable list and finite field registered since
  the state offset, so a sibling registering one between the two encodings changes the bytes.
- `ready_late_native_fault_after_cancellation_disallows_pause`: the other tickets wait until ticket 0 is inside
  its visitor, so a later commit (hence a checkpoint callback) always observes it and cancels.
- `ready_changed_parked_prefix_fails_before_any_suffix_admission` / `run_pause` (a flake the contention run
  found, 15.6 % of runs): the pause predicate also requires all 18 domains admitted, and tickets >= 2 wait until
  tickets 0 and 1 have emitted their prefixes; before, a mounted ticket >= 2 with an accepted Count event could
  be paused on together with one of tickets 0/1.

## 4. License-gated tests (review #17, plan §6.8)

- `crate::test_gates::licensed_or_skip(test)` (app and core) replaces every silent
  `if !LicenseManager::is_licensed() { return; }` gate in test code (35 gate calls in 12 files, the local
  `licensed(test)` helper of the parallel tests included). The owner-batches driver test already asserts the
  license and so fails without it. Without a license the gate writes
  `SKIPPED <test>: SYMBOLICA_LICENSE absent ...; the test exercised nothing and passes vacuously` to the real
  stderr (past libtest's capture, so it shows in every suite run); `test_gates::skip` does the same for the
  other vacuous gates (fewer than 2 cores, workers unavailable).
- `crate::test_gates::workers_or_skip(test, workers)` (app and core) gates the W>1 variants of worker-loop
  tests on the host core-budget preflight: when the preflight fails for lack of the license it goes through
  `licensed_or_skip`; otherwise it skips visibly with the preflight error (e.g. W50 on a 16-CPU affinity mask).
  It replaces preflight gates that bypassed strict mode (owner-batches and frontier-policy worker helpers,
  delegation control, refined-successor subdivision) and seven that were fully silent (three in
  `tests/parallel_walk.rs`, two of them whole tests; `native_walk_cancellation_at_alias...`;
  `initial_overlap_actual_native_residual...`; and core `k6_wave` x2, both whole tests).
- Strict mode: `RUSTRED_TESTS_REQUIRE_LICENSE=1` turns every license skip into a failure. Plan §6.8 asks that
  epoch soundness tests fail rather than skip without the license; those tests do not exist yet (W2), so the
  mechanism is the opt-in variable plus the gate helpers for them to call.
- Without the license, an unfiltered suite does not pass vacuously [M, `TMP/ops/nolicense-step3/`]: the
  multi-threaded runs of both lib suites abort (SIGABRT) because unlicensed Symbolica aborts when used from a
  second thread; single-threaded, the core suite still aborts at an ungated test that spawns its own threads
  (`concurrent_context_construction_reuses_deterministic_positional_symbols`), and the app suite reports
  28 failures (ungated tests that need the license, e.g. the owner-batches driver tests, which assert it).
  Pre-existing behaviour, unchanged here.
- Gate check [M] (`TMP/ops/nolicense-gates-step4/results.txt`): each of the 42 gated tests run alone
  (`--exact --test-threads=1`) without `SYMBOLICA_LICENSE`: all 42 pass with a visible SKIPPED marker by
  default, and all 42 fail under `RUSTRED_TESTS_REQUIRE_LICENSE=1`. Before `workers_or_skip`, 12 of the
  then 35 gated tests still passed in strict mode (`TMP/ops/nolicense-gates/`).
