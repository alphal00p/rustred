## 1. What was built

### 1.1 Request policy

`--g2-residual-anchors off|union` (library `OwnerDomainWalkRequest::g2_residual_anchors`,
`OwnerDomainWalkG2ResidualAnchors`), default `off`. `union` requires `--transfer-unreserved-lookahead H` (the
responsibility ledger), excludes physical Apply subdivision and owner-batched publication, and is bound into the
checkpoint request digest (`"g2_residual_anchors":"union"`; `off` adds no key, so every existing binding,
checkpoint and control stays byte-identical). The shard supervisor accepts it as an immutable native option.

### 1.2 Planning (dispatch time, on the inspector)

A job is eligible when its domain Q is an Apply domain with ID >= the initial prefix (R1: initial IDs are never
planned) and no initial-D-band plan applies (the initial-overlap plan keeps precedence). The inspector:

1. enumerates Q's lattice points (at most 2^18; an unbounded or larger Q is inspected whole);
2. queries the anchor index of Q's (Apply, owner) bucket for every entry with `stamp < snapshot` whose interval
   shape meets Q (§1.3);
3. walks Q's D levels from the top down, then from the bottom up, keeping a level only if every point of it lies
   in some candidate (exact interval membership; already-used anchors first, then the oldest candidate);
4. confirms every assignment with the native `DomainPowerSummary::contains` of the one-point domain (authority);
5. inspects the D band between the covered top and bottom runs (ONE piece; nothing when every level is
   covered: a "full cover", no native call). Covered interior levels stay inside the band (re-inspected), so
   the residual is at most one piece (the census: D-only residuals are 1 piece in 2,284/2,298 gen-7 partials).

Snapshot stamps. A record's merge stamp is its position in the publication stream (the ledger's publication
count at its publication, equal to its record index in the sidecar). A plan uses only anchors with
`stamp < snapshot`, and the job publishes later, so `snapshot <= own stamp` and anchor links strictly decrease the
stamp: responsibility is well-founded in merge order. Ready walks read the current publication count (every
anchor with a smaller stamp was indexed before the count was published). Ordered walks use the deterministic
snapshot `id + 1 - H` (the dispatch fence `cursor + H` guarantees every ID up to `id - H` is published before
`id` is dispatched), so an Ordered G2' walk is reproducible across widths and across pause/resume.

Anchor kinds (lent scopes): a Native Apply record with 0 frontiers lends its domain; a G2' residual record lends
its domain (its residual was inspected and the rest of it was covered by its own, older anchors); an
initial-D-band partial lends only its inspected low slice D <= cut - 1 (W2 protocol §7 R3). G2' full covers are
not indexed (every point of one is covered by its own older anchors, so indexing it adds no coverage). Records
with a frontier or an error are never anchors.

### 1.3 Indexed anchor search (no linear scan)

Per (Apply, owner) bucket (`walking/g2/index.rs`): immutable runs sorted by the Morton key of the lower corner,
each with a hull tree (leaves of 16 entries, fan-out 16; a hull holds per-axis min lower / max upper, the A, R, D
interval envelope and the minimum stamp), plus an append-only tail of 1,024-entry chunks. The coordinator only
appends to the tail (one `OnceLock` slot write); a planning inspector that finds a full chunk pending seals it
into a run and merges runs geometrically (older <= 2 x newer; ~15 copies per entry at 2e7 entries, <= 10 runs, by
simulation) under a `try_lock`, so no planner waits on another. Readers take an `Arc` view that always holds
every appended entry exactly once. A query descends only into hulls that meet Q's box and aggregate intervals and
whose minimum stamp is below the snapshot, and filters leaves exactly the same way. Entry size 136 bytes
(the exact 96-byte compact domain of the lent scope, its interval shape, stamp, ID, kind).

### 1.4 Records, ledger, closure

A planned job publishes a `g2_residual_anchor_inspection` record (`native_inspection_scope`
`g2_residual_D_band` or `none_covered_by_g2_anchors`) with a `g2_residual_anchors` block: merge stamp, snapshot
stamp, residual power bounds and D band (or null), residual pieces (0 or 1), anchors `{id, stamp, kind, scope}`,
query/covered points and candidates. Every anchor gets a dependency edge. The ledger keeps a G2' log (one row per
published Apply native record, in merge order: ID, kind, stamp, snapshot, band, anchors; `delegation/g2_log.rs`)
and re-checks every link when the coordinator records it (anchor published with 0 frontiers, same bucket,
admissible kind, stamp equal to its logged stamp and below the snapshot, snapshot <= own stamp). Resolution walks
the log in merge order: a G2' record's status is its residual's status, else its anchors' resolved statuses
(`discharged_by_residual_and_g2_anchors`). The in-memory ledger entry keeps its size (the row index fits the
padding).

### 1.5 CP5 persistence, restore validators, pinned plans

A new segmented section `anchors` (tag `G2LG`, 48-byte rows then the u32 anchor IDs; append-only, so a save
writes only the rows since the previous generation) is present iff the walk runs with G2' (absent, not even
`null`, otherwise). Restore attaches the log to the ledger and validates it: rows in strictly increasing stamp
order, every published Apply native logged exactly once, Ordered stamps equal to IDs, kinds agreeing with the
ledger (initial-D-band iff an initial anchor), no G2' row on an initial ID, every anchor an admissible merged
record of the same bucket with its logged stamp below the snapshot, snapshot <= own stamp, anchor edges present
in the dependency graph, and the exact cover `Q <= residual u anchor scopes` decided by
`lattice::Cell::covered_by_union` (enumeration fallback when the region budget cannot decide). The anchor index
is rebuilt from the log at session start. A job whose stream holds accepted events at a save (Ordered publisher,
Ready active and parked tickets) has its decision persisted as a pin in the checkpoint progress
(`g2_pins`); the resumed job re-runs exactly that decision, so its replayed prefix matches.

### 1.6 Oracles

`rustred walk-verify-closure` (`verify_closure.rs`, `check_g2`) re-derives each record's publication position
from the record order and checks: Apply, not an initial record, recorded merge stamp = position, snapshot <=
position, residual a D band of Q, every anchor with its edge, its true position as stamp, position < snapshot,
same bucket, an admissible and sealed kind (Native, initial-D-band partial with its low slice, G2' record with a
residual), then the exact multi-target cover by `covered_by_union` (region budget 2^18), cross-checked by
enumeration on small Q. F10 re-inspects the recorded residual (a full cover must record nothing). New mutations:
`g2-shrunk-residual`, `g2-late-anchor`, `g2-inadmissible-anchor`, `g2-dropped-anchor-edge`, `g2-anchor-cycle`.
The Python audit (`audit_owner_domain_walk.py`) does the same from result.json with its own interval
region-splitting cover predicate (independent of lattice.rs and of the engine), cross-checked by lattice
enumeration on small Q; `oracle_mutation_matrix.py --g2-run` adds the G2' rows for both oracles.
