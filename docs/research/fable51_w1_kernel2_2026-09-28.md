## 1. Evidence that motivated the change [M]

W2 comparator runB (`TMP/w1/comparator/runB/`, binary `rustred-fp-36c60fb8`), coordinator thread:

| Source | Finding |
|---|---|
| fp window T+181 s, 16,329 samples (`perf-early-coordinator.data`, flat srcline) | `__memmove_avx512_unaligned_erms` 39.6% of samples (self); `blocks.rs:669`/`:663` (reverse word loop, first touch of the block) 10.6%; `fold_ge` 5.7%; **`index.rs:802` (`Split::rejected` partition_point) 4.0%; `index.rs:552` (`find_controlled` partition_point) 2.7%**; `may_be_contained` 3.9% |
| DWARF window T+~720 s, 1,243 samples (`perf-dwarf-coordinator.data`) | `retire` inclusive 50.8%, of which `slice::swap::<Meta<15>>` 31.0% (memmove leaf 25.1% via `copy_nonoverlapping<Meta<15>>` in `swap`, 23.8% on the prepared path, 1.3% on the serial path); `Block::reverse` 15.9%; `find_from` 15.1% |
| duty buckets (fp windows) | ordered_commit 89.9% / 91.6% of samples; progress_json 1.7% / 0.9%; set_parallel_telemetry 1.9% / 1.3% |

The compaction loop after each eligible group's scan was
`for read in 0..old_len { if keep(read) { meta.swap(kept, read); blocks.swap(kept, read); kept += 1 } }`: it
touched every row of every eligible group on every retirement and swapped a 144-B `Meta<15>` even when
`kept == read` (a self-swap through `ptr::swap`'s overlap-safe copy, hence memmove).

## 2. What changed

| Commit | Content |
|---|---|
| 71062d77 | retire compaction starts at the first empty row and swaps only when `kept != read` |
| 43269bc2 | watermark shortcuts in `find_controlled` and in the prepared split (`Split::rejected`) |

- **Compaction** (`queue/index.rs`, `AggregateIndex::retire`). The scan loop records the first row whose length is 0
  after its retain (or was 0 before). Compaction starts there; a kept row is swapped into place only when an earlier
  row was dropped. A retirement that empties no block copies nothing.
  - *Identity by construction.* Before the first empty row, the old loop only executed `swap(i, i)`. From there on,
    the new loop performs the same swaps as the old one except the self-swaps. So group order, block partition,
    the pinned tail, the removed groups and the dropped rows (whose exact-envelope bytes the running totals
    subtract) are those of the old loop, also for CP5 images restored with empty rows mid-group (the validator
    admits them; the old loop dropped them at the next eligible retirement, the new one does too). Callbacks and
    charges happen in the scan, which is unchanged.
  - The scan now reads `meta.len` for every row, including rows the envelope rejects (one extra load per row on a
    row the envelope test has just read).
- **Watermark shortcuts** (O(log) searches, 6.7% of the fp-window samples above).
  - `find_controlled`: `first_id == 0` skips nothing without a search; a group whose last row lies wholly below
    `first_id` is skipped without a binary search over its 144-B rows (a revalidation above the snapshot watermark
    usually finds every block of an eligible group below it).
  - `Split::rejected`: a rejected run (ascending IDs) wholly below `first_new` needs no `partition_point`.
  - Both return the value of the search they replace whenever the search is over a monotone predicate, which the
    layout guarantees (IDs increase within and across the non-empty rows of a group). With empty rows mid-group
    (restored images only) the `find_controlled` shortcut can skip rows the search would have visited; every such
    row is empty or wholly below `first_id`, so it would have been passed over without a charge or a callback
    (only the uncharged cancellation poll count differs).
- **Tests** (`queue/index/tests/blocks.rs`):
  - `retire_compaction_keeps_the_historical_layout`: 8,000 random admissions (signature runs, ID windows that empty
    whole blocks mid-group, 5% random retirements, pinned tails, group removal) against a reference model of the
    historical layout rule, with the running totals equal to the full walk after every step.
  - `retire_drops_restored_empty_rows_even_without_retirements`: a restored image with empty rows mid-group and an
    empty tail, retired with nothing retiring, pinned and unpinned.
  - `watermark_shortcuts_keep_minimum_ids_and_the_prepared_split`: forward minimum-ID results against brute force
    (watermarks 0, random, at and above every ID), and the prepared split with a word prefilter (decided old IDs, new
    IDs handed to exactly one of prefilter and predicate, retired set, layout).
