## X budget failure and bounded correction

The initial X solve reached output construction but failed with
`candidate aggregate collection-entry budget exceeded` under the default
one-million-entry policy. It exited unsuccessfully after **121.62 s** wall,
364.76 s CPU and 1,453,172 KiB peak RSS; no usable bundle was saved. That attempt
is not included in the successful-run timing table and is not a completed timing.

The successful retry used explicit caller-owned bounds of 1 GiB serialized
bytes, 512 MiB aggregate coefficient text and eight million aggregate collection
entries. X alone contains 1,263,962 table-array records: 640,274 RHS terms,
602,935 source records, 19,980 rules, 445 residuals and 328 sectors, before
additional exceptional-case arrays. Its raw payload also exceeds the ordinary
256 MiB artifact limit. Thus both larger allowances address measured sizes.

The candidate codec now has a separate symmetric 1 GiB ceiling for explicitly
enlarged policies. Defaults remain 256 MiB, and certified-artifact limits and
schemas are unchanged. Existing checked accumulation of coefficient bytes and
collection entries remains in force. Wire limits do not promise an RSS limit.
CLI/Python default-budget surfaces have not acquired a larger-budget switch.

## Reproduction and revision boundary

RustRed **`13bc9474` is published** and contains the candidate-only ceiling,
library/CLI feature separation, offline helper and budget tests. GammaLoop's
current RustRed and RustRed-app pins both reference this revision. Its runtime
API already accepts the explicit eight-million-entry caller policy used by the
new Vakint loader.

However, the helper **at that commit** still uses the default one-million-entry
count. Successful X generation used the subsequent helper amendment published
in **`91751eb2`**: `max_collection_entries: 8_000_000`. Reproduction of all four families must
use a RustRed revision containing that helper amendment, or the same
explicit caller setting through the existing Rust API. Do not instruct users
to regenerate X with the unmodified helper at `13bc9474`. This does not require
regenerating the other three bundles or changing the runtime schema.

After building the helper from that revision, run from the RustRed checkout with
the license already set in the environment; keep all temporary paths inside
the workspace:

```sh
cargo build --release --locked --offline --no-default-features \
  -p rustred-app --example candidate_bundle

target/release/examples/candidate_bundle generate \
  /path/to/gammaloop/crates/vakint/data/rustred/four_loop/x.toml \
  9 6 default TMP/new-x.candidates.toml TMP/new-x.report.toml

# Separate process; no source search is performed here.
target/release/examples/candidate_bundle verify 10 \
  TMP/new-x.candidates.toml \
  /path/to/gammaloop/crates/vakint/data/rustred/four_loop/x.rrcat

gzip -n -9 -c TMP/new-x.candidates.toml > TMP/new-x.candidates.toml.gz
```

Use nonpositive coordinate list `9` for H/X and `8,9` for FG/BMW; output paths
must be new. The measured generation commands additionally used
`taskset -c 80-85` and `/run/current-system/sw/bin/time -v`.

The focused regression command was:

```sh
CARGO_PROFILE_RELEASE_LTO=off cargo test --release --locked --offline \
  -p rustred-app --no-default-features --lib \
  application::candidate_bundle::tests -- --test-threads=1
```

`candidate-bundle-tests.log`, and the preserved helper executables/raw bundles.

## Corrected oracle and completed focused checks

The new cancellation tests exposed a real sign error in the existing FMFT
adapter: the FG basis needs `k4 = -p6`, not `+p6`. The correction preserves
absolute denominator IDs and uses signed IDs in numerator scalar products.
The focused FG/D7 versus P7 numerical regression now passes (0.71 s), while
its pre-correction failure remains recorded. A pure-Symbolica regression
checks all 19 registered four-loop classes and all 123 physical edges.

The corrected FMFT oracle re-evaluated all 1,155 declared terminals in
199.29 s: H 386 unchanged, FG 145 with four corrected numerator projections,
BMW 179 unchanged, X 445 unchanged. The shipped catalogs are byte-identical
to the fresh outputs. A subsequent FG check without the refresh/output option
passes with zero differences (23.62 s). No IBP program was regenerated for
these catalog corrections.

Focused release tests also pass: one signed-routing test, seven
default/support/mass regressions, and three public four-loop loading,
descriptor-binding and unexpanded-master-mode tests. The latter take 99.14 s
and peak at 12.67 GiB; their boundary includes the raw FG test plus four
sequential cold loads, not a single initialization or solver benchmark.
