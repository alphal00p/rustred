# Saved-rule application of finite numerator-symmetry rows

This isolated research tool uses exact, native public RustRed services. It does
not generate ordinary IBPs, enumerate new physics inputs, modify a production
campaign, evaluate numerical masters, or claim a minimal master basis.

`study.rs` is the generic optimized driver exercised on 22 October 2026. The
optional source selection is input data: there is no dispatch on topology names,
loop count, or the P102 regression. The unpublished development-only projection
reader was **not** part of the executed build and is not included here.

## Input and authority

The positional native arguments are:

```text
study BASELINE.rrbin SYMMETRY.rrbin PUBLICATION/artifact.json SELECTION.json NEW_OUTPUT
      [--workers N] [--max-numerator-degree R]
      [--source-key INDEX_TUPLE.json] [--fewest-active-lines-first]
```

The baseline must be a compact, authenticated, relations-only session with zero
ordinary-source cursor and no pending rebuild. The symmetry capsule is cold
decoded against that exact family: its complete momentum-change witnesses and
transported numerator equations are independently replayed by existing core
services. The published report binds the selected candidate programs and all
owner routes, including domain-rule overlays. The public
`prepare_saved_integral_equations` adapter applies **complete homogeneous rows**
under finite exact-point source admission; descendants are not rank clipped.

The source rank option selects which finite source equations to study. It does
not certify a numerator-rank domain or exclude higher-rank transformed children.

The default group order is `(negative-index degree, total equation terms,
coefficient terms, exact source tuple)`. `--fewest-active-lines-first` inserts
positive-support size and positive-power excess before equation term counts.
All witnesses for a selected source are processed together. A pending native
provider key acts as a finite deterministic job ticket, not a manufactured
integral identity. Receipts retain the actual source key and witness ordinal.

Every coalesced saved reduction retains its conditions. If application fails,
the original complete witnessed equation remains an exact auxiliary row, with
a typed diagnostic; no unknown leaf becomes a master. Even an exact zero row
retains any additional conditions. Before insertion, native hash/equality only
removes conditions already present in the session; it never approximates zero.

The saved formulas retain their original candidate-rule provenance. A new
symmetry witness is independently verified, but this experiment does not turn
its saved application into an independent replay certification of every IBP.

## Build and run

Compile `study.rs` with `rustc --edition=2024 -C opt-level=3` against matching
**release** `rustred`, `rustred_app`, `serde_json`, and `blake3` libraries from one
Cargo dependency graph. Supply the corresponding dependency/native-library
search paths. Do not mix Symbolica instances from different feature graphs.
The normal release Cargo build prepares those libraries; this lightweight
external driver avoids rebuilding the engine for cohort/order experiments.
Compilation is excluded from reported timings.

The optional Python supervisor accepts a caller-specified CPU set and memory
allowance without imposing an additional count, rank, time, or memory ceiling:

```bash
python -B tools/research/numerator_symmetry_saved_rows/run.py \
  --executable /absolute/path/to/optimized-study \
  --baseline /absolute/path/to/baseline.rrbin \
  --plan /absolute/path/to/native-symmetry-certificate.rrbin \
  --publication /absolute/path/to/pinned-publication/artifact.json \
  --selection /absolute/path/to/immutable-inputs/selection.json \
  --output /absolute/path/to/new-evidence-directory \
  --cpus 0-3 --max-memory-bytes 128000000000 \
  --max-numerator-degree 1 --fewest-active-lines-first
```

For an individual regression, pass `--source-key /path/to/key.json`, where that
file contains a plain signed integer array in the pinned family's actual basis.
Its full source group is selected, not an individually hand-written relation.

## Output and limitations

Each processed row has native Symbolica coefficients and conditions in a
content-addressed `rows/*.rrbin` evidence envelope. Its structural JSON stores
only integer indices, coefficient IDs, and provenance—not algebraic strings.
The adjacent JSON views are for inspection and are not mathematical authority.

`progress.json` records every completed row. The native session is saved after
a group that changes the exact row space, or after a 60-second checkpoint
interval; the checkpoint records only **completed groups**. At success,
`result.json` and `numerator-symmetry-result.rrbin` contain the complete selected
cohort result, cold-loaded exact maps, and preserved source identities.

This experimental driver has **no automatic resume implementation**. A manual
interrupt preserves the last completed-group native snapshot and per-row
receipts, but an in-flight row/group is not a resumable result. Start a new
evidence directory for another experiment. The production campaign's normal
fresh-round/resume interface is separate.

Always independently compose the old maps through the final maps and verify
guard containment. Do not add dependency counts from overlapping experiments.
The saved finite basis is nonminimal unless a separate argument proves otherwise.

This source-order experiment does not change the production provider's eager
saved-rule application policy. Enabling both numerator and saved-rule assistance
in the normal refinement CLI still prepares/applies the full row inventory.
For the initial fresh `(2,0)` round, use numerator symmetry assistance with
`--no-saved-rule-assistance`; that keeps the measured cheap raw-symmetry pass
without repeating the expensive full saved-application scan described below.
